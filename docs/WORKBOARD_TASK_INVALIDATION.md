# Preserve geometry caches when a hunting task ends

The actual authored native V18 100-resident/60-structure workload repeatedly cancelled hunting tasks. In the first180actual steps, all55full WorkBoard resets came from hunting.finishTask. These actor-only cancellations cleared obstruction results and invalidated navigation component bookkeeping even though they changed no terrain, solid footprint or owner. Inventory-water delivery was an initial hypothesis, not the measured cause; no water callers are changed.

WorkBoard.invalidateTasks now clears task lists, next-review time, occupancy scheduling and node-component lookups while retaining the navigation labels/revision and exact-footprint obstruction cache. Clearing node components is essential because prey and resources can move. The next task rebuild still runs refreshObstructions, which checks current world/state identity and exact solid footprints. Cached resource obstruction results still recheck each resource's coordinates. Actual topology changes still rebuild labels through navigation revision checks. Full reset remains in geometry/ownership callers and in prey death and exhausted-carcass branches.

Only hunting.finishTask uses this narrower invalidation. Hunting behavior, reservations, retries, danger, exploration, task order and priorities are unchanged. No work cadence or NPC tasks were reduced. Synchronous per-team reserve, season, camp position and wood/stone priorities are also reused within one refresh call; no cross-tick scalar cache is introduced. Fish are deliberately still read from the live array after dock queries can survey new grounds.

At180steps, both runtimes performed68refresh calls,37full task rebuilds and31fast returns. Exact obstruction cache clears fell37→4 and navigation revision rechecks51→5; actual label floodfills stayed5. All55cancellations became task-only invalidations. At3600steps/120simulation seconds, both performed1527refresh calls,638full task rebuilds and889fast returns. Obstruction clears fell628→33, label revision rechecks749→38, and actual label floodfills stayed11. Candidate retained23other full resets and used776task-only cancellations.

These counts come from bounded test-only probes of NON-sampler methods. Up to256reset callsites are sampled into at most32reason buckets; later calls still count globally but are not fully attributed. No sampler or prototype was replaced. Static terrain cache results were unchanged:1build/9hits at180steps and1build/19hits at3600. Full ordered node/kind/slot/priority traces on every task rebuild, every-step assignment-choice traces, full snapshots and external RNG every30steps and final state matched exactly. Both final strict saves validated, clocks advanced and no simulation errors occurred. Raw checkpoint artifacts preserve the evidence.

Thirteen focused tests passed: existing cache controls; actor-only task invalidation; collision/movement, gates, plans, deaths, ownership, footprints, world/state replacement, topology and moved resources; plus four native season/reserve/age/dock-survey scenarios against the exact old refresh oracle. Those scenarios compare full task arrays and all query-induced state mutations. Typecheck and production build pass. The five focused existing hunting/projectile/route/flight/militia files also pass29/29cases, including real hunting, butchery and finite camp delivery.

This is measured redundant-work elimination, not an FPS claim or smooth-play acceptance. The earlier Chrome WorkBoard.refresh timings motivated the fix, but no before/after browser benchmark has yet qualified it. No player save or private browser content is included.
