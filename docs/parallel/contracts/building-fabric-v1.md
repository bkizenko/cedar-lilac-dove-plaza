# Paid building fabric v1 — backend contract

Source candidate, not qualified or activated by a new UI. Existing ordinary housing conversion remains supported.

`beginEraUpgrade(g, buildingId, 'rebuild' | 'extend', side?, team=0)` in `housing.ts` returns `{accepted, reason}`. `eraUpgradeIssue` in `buildingFabric.ts` supplies admission. `fabricContext(b)` is a pure, optional `{eraMode:'fixed', built:{era,wealth}, extensions:{era}[]}` adapter for Experience; it never calls scene code. If metadata is absent it returns undefined. `eraUpgradeBenefits` reports completed count and current/repairable maximum HP. No UI or scene integration is included.

Optional `Building.fabric` is `{version:1,built:{era,wealth,legacy?:true},baseMaxHp,upgrades:FabricCompletion[]}`. New supported buildings snapshot their owner’s current era; old supported buildings are stamped at load/first intent, explicitly marked legacy, with their existing HP/maxHP and zero receipts. Wealth starts at neutral zero rather than inventing historical prosperity. This migration grants no bonus. Completed receipts retain mode, exact original/target rectangles, building type, target era, side/growth if extended, paid owner/materials, work seconds, completion time and maker ID. At most two paid completions. Legacy absence remains valid.

Named `ERA_UPGRADE_RULES` tune rebuild 24 logs/8 stone/48 work seconds, extension 48 logs/16 stone/96 work seconds, existing eight-unit physical packets, and +15% of recorded base maxHP per completion. Current HP never rises on completion; existing paid maintenance can fill the added repairable durability. No population, inventory capacity or throughput is synthesized. Rebuild needs newer local techniques; a same-era extension pays for real added ground. Eleven explicit dry building classes are supported; plots, ports, defences and landscape works return a specific unsupported reason.

Both modes reuse `HousingRenovation` source/cache/body/site payment, pause, interruption, death, capture and retained-project custody. Added modes `rebuild`/`extend` require strict `eraChange` `{version:1,type,targetEra,original,target,side?,growMetres?}`. Payment happens at an actual cache; all paid material must reach the actual site before labour. Completion is owned by the same living project builder and is idempotent.

The original structure/footprint stays in use while the exact shifted full wing reserves placement space. World `extensionTerrainCheck` remains unchanged and runs at admission/completion, supplemented by full reservations and all living body checks. The builder physically exits a future wing with ordinary steering. Only then x/z/w/d commit together, walk/navigation rebuild, and completed durability applies. No flattening, collision shrink, teleport, instant capacity or healing.

`housingValidation.ts` consumes `validFabricState` and `validEraRenovation`, including retained destroyed-target intents. Seven controlled actual-Game tests are prepared for physical paid rebuild, shifted extension/two-upgrade cap, legacy/malformed saves, unchanged housing conversion, living obstruction, death and capture. Tests are UNRUN at source handoff; no native-terrain or published gameplay credit.

Experience follow-up: consume `fabricContext` and update its own era default/rendering. Current `civBuildings.extend` compacts the base inside its supplied footprint; it must not replace the backend’s actual shifted original/wing geometry or imply extra physical capacity. UI admission should use saved IDs and the backend result, with preview and commit sharing the same issue/terrain rules.

Experience can route its selected-building action through existing `await engine.dispatch({kind:'begin-era-upgrade',buildingId,mode:'rebuild'})` or `{kind:'begin-era-upgrade',buildingId,mode:'extend',side:'north'|'south'|'east'|'west'}`. No team/entity/price/stat fields are accepted. Selected person IDs are captured by Engine and revalidated before normal native queue allocation. `era-upgrade-pause` takes `{buildingId,paused:boolean}` and only handles these two fabric modes, preserving the paid packet ledger. The standard epoch/sequence acknowledgment and owner cache invalidation apply. Consumers must ignore stale session acknowledgments, display the actual rejection reason, and never fall back to direct display-Game mutation.

`await engine.readModel({kind:'building-fabric',buildingId})` returns the normal epoch/request/revision/navigation/CPU envelope with model `{kind,buildingId,context,benefits,work?,choices}`. `context` is detached saved `fabricContext`; `work` copies mode, phase, progress, duration, paid, paused and optional blockedReason. Exactly five choices (rebuild + four sides) carry issue, finite material quote, workSeconds, and optional target rectangle when admitted. One requested owned living building per query; foreign/absent IDs reject. Use the existing mounted `useOwnerReadModels` hook and 500ms coalesced cache, rather than querying all buildings each frame. Queries may initialize owner routing caches; never call them on a renderer projection. Cached choices are advisory: commands revalidate every admission.

Four additional owner-adapter contract tests are prepared UNRUN: exact flat schema, detached bounded owner facts, stale/ID admission and no remote spend/heal, and project-preserving pause/resume/foreign refusals.
