## Proposed persisted field

Future ScoutProvisions retains `version:1; food; foodUsed; water; waterUsed; started` and adds optional `foodCustody?: PackedFoodCustody<FoodKind>`:

- `PackedFoodCustody = {version:1; legacyUnits:number; lots:PackedFoodLot[]}`.
- `PackedFoodLot = {kind:FoodKind; units:number; origin:{team:number;anchorKind:'camp'|'building';buildingId?:number;x:number;z:number;loadedAt:number}}`.
- Origin records a physically reached cache location and historic food provenance only. It does not claim a bag, pottery vessel, container asset or additional storage capacity. `loadedAt` is a custody timestamp, not a freshness reset.
- Each lot preserves the actual physically reached load cache. Transfers merge only identical kind AND identical source origin. Origin is historical provenance, not permission to debit a remote/destroyed cache or force return to an inaccessible original cache; actual current owned supplyReached is required at return.
- `food = legacyUnits + sum(lot.units)` remains PHYSICAL food units. `foodUsed` remains PHYSICAL eaten units for current sea/camp counters. Neither is nourishment. Lifetime physical capacity100 and bounded64lots reject admission/transfer atomically without truncating identity or relocating goods.
- Absence of foodCustody is explicit legacy unknown scalar custody, coefficient1, existing old-save return as generic provisions. Never infer a kind from current inventory or label old food as bread/curd. Mixed transfer into a legacy pack promotes only the envelope: existing unknown quantity becomes legacyUnits; typed incoming lots retain identities. Untyped amounts stay unknown.
- Canonical policy supplies ordered FoodKind catalogue, edible kind predicate and FOOD_NOURISHMENT values. New leaf does not duplicate curd/bread balance values. Generic kind parameter lets focused kernel tests cover freshCurd/whey without editing FoodKind before curd integration. Future live adapter must use the merged actual catalogue, not string casts.

## Proposed leaf API

`planPackedFood(stock,requiredNourishment,origin,catalogue,maximumUnits=100)` returns complete typed custody or null; it never debits inventory. Proportional actual edible lots meet the nourishment budget while retaining physical quantities; no cap-based retyping. Existing raw grain/fish emergency handling must be a deliberate policy, not accidentally treated as ready ration. `packedFoodNourishment` and `packedFoodUnits` expose distinct dimensions. `consumePackedFood` consumes actual typed quantities to meet nourishment and returns consumed lot/unknown breakdown; it increments physical foodUsed only. `transferPackedFood` atomically moves actual kind+origin quantities and explicit legacy unknown units. `resetPackedFoodUsage` returns prior physical usage and resets only that counter. `withdrawPackedFood` returns actual custody payload for reached-cache refund, loss or capture transfer and never reclassifies kinds. `validPackedFoodCustody` validates bounds, kinds, source IDs/team/time/coordinates and scalar-to-lot equality.
