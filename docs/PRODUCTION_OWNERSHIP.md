# Paid production ownership and physical unloading

Food, hides, grain, flour and pottery retain their existing paid project records. New shared coordinator claims own the actor and the actual processing slot; they do not duplicate or refund ingredients. Acceptance reserves those claims before spending the batch inputs. Runtime claims reconstruct from saved projects before tree, construction or haulage admission can take their owners.

| Project phase | Actor ownership | Physical space |
|---|---|---|
| Carrying paid inputs | Original carrier | Reserved target processing slot |
| Working | Actual maker | Processing slot |
| Passive curing | No maker occupied | Loaded rack/shelter slot remains reserved |
| Ready for pickup | No actor until a real eligible pickup adult accepts | Finished batch retains slot until collected |
| Returning with output | Original output carrier | Processing slot released |
| Paused while carrying | Original carrier remains responsible for the real load | Original reservation preserved |
| Unloading inputs | Original carrier walks to a reachable real cache | Target slot released; no goods credited |
| Stored paid inputs | No actor | Reserved committed-batch cache space; input stock remains unavailable |
| Collecting parked inputs | Replacement walks to the saved cache location | Both cache space and target slot reserved until actual pickup |
| Complete/lost | Released | Released |

“Unload batch at cache” is a physical command. A carried input batch returns with its original body. Only after actual arrival and storage-capacity admission does it become an anchored, ownerless paid parcel; the resident can then take other tasks. Its paid inputs, progress and original freshness clock remain on the project. Nothing is simultaneously refunded into available inventory.

Resume atomically obtains a real eligible replacement and target slot, then walks that person to the saved cache anchor before carrying the same inputs to the workplace. If the camp moves, the old parcel does not teleport. Blocked access, full target slots or insufficient cache space leave prior ownership/claims intact with a concrete reason. Carrier death loses a carried load; a dead empty pickup adult leaves the anchored parcel available for another person.

Returning finished batches use actual output delivery rather than being reclassified as unpaid ingredients. Unloading or returning can continue even if the original workplace has since been destroyed. Inventory is credited once on physical delivery, with actual firing losses preserved.

Move orders remain available with a paid load. Direct gathering/building explains that the actual carrier must unload; it does not misreport the tree as full or silently steal the actor. Explore automatically queues physical paid unloading, then begins its provisioned expedition after actor release. Builders may retain future queued intentions; these do not make a resident a permanent builder.

Shared `JobCoordinator.amend` replaces actor/capacity claims atomically: failure retains all previous claims. Passive drying therefore releases hands without releasing its loaded place, and pickup cannot take an actor from another shared job. Project progress and perishable exposure remain executor-owned. Paid parked materials occupy finite communal material-space units alongside stored goods, preventing a parking/refund loophole.

Diagnostics expose production project/actor/passive/stored counts, rebuilds, claim changes and conflicts. Strict saves validate physical slot capacity, anchored stored/collecting parcels and ownership references. Contributor/practical-learning hooks record real staffed progress and actual useful delivery; pickup alone does not invent maker experience.

This migrates production actor/slot/cache ownership, joining the existing tree, construction and haulage adapters. It does **not** complete the master plan’s all-executor goods-reservation gate: all legacy equipment, journeys, trade, water and building-material reservations still require their separate integrated audit.
